# 05 ? Judge Demonstration Guide

## Five-minute walkthrough

| Step | Presenter action | What to demonstrate |
|---|---|---|
| 1 | Launch both servers using the root README; open localhost:3002 | Running browser interface and healthy API |
| 2 | Register a new student account using your own demo details | Authentication and role selection |
| 3 | Select Network Security and Endpoint Security and complete onboarding | Topic selection and learner setup |
| 4 | Begin a training session | Session plan, scenario text, four defensive choices |
| 5 | Select an action and submit | Verdict, explanation, XP change, next scenario |
| 6 | Pause and resume from the dashboard | Preserved session state |
| 7 | Complete the session or end it early | Debrief and stored history |
| 8 | Open progress views | Recorded attempts, topics, and learning feedback |

Opening statement: ?CyberShield helps learners practise defensive cybersecurity decisions through scenarios, feedback, and tracked progress. This demonstration uses built-in fallback content; live AI integrations are available through private backend configuration.?

Show `02_System_Architecture_and_Workflow.md` to explain how the five agents are coordinated. Show `/docs` if judges want to inspect the API surface.

## Evidence to capture for an optional recording

Record the landing page, topic selection, scenario with four choices, feedback, and progress after a session. Keep registration passwords, developer tools containing tokens, and environment files out of the recording. A suggested duration is three to five minutes. No recording is included or claimed in this submission.

## Claims to keep accurate

The shipped mode uses local fallbacks. AI quality, production scalability, educational effectiveness, and a public deployment have not been established by this demo. Some alternate dashboard components contain illustrative data; use the actual session and progress flow to demonstrate persisted activity.
